# FIN-04 evidence package

What the HackMatrix final-round brief asks teams to submit, mapped to files and commands in this
repository. Every number comes from synthetic Kestrel-Sim worlds: it shows behaviour under the simulator's
assumptions, not accuracy on real bank data.

## Setup and commands

```bash
cp .env.example .env && make setup
make demo              # migrate, seed world 42, train M5/M6/M7 (≈10 min), detect
make replay            # Addition 1: five arrival orders → ml/reports/replay/
make train             # Addition 2: retrain + FIN-04 evaluation → ml/reports/fin04_eval.json
make eval-behaviour    # M1/M2 vs rule baselines → ml/reports/m1_m2_eval.json
make test              # backend tests
make api / make web    # the application
```

## Data

| Item | Where |
|---|---|
| Source | Kestrel-Sim, a seeded agent-based simulator of a fictional co-operative bank (`data/kestrel_sim`). No real people or accounts. No external datasets were used. |
| Permissions | Generated by the team; Apache-2.0 |
| Scenario suite | `data/scenarios/scenarios.yaml`: S1–S8, each with a legitimate twin that differs by one fact |
| Live evening | Held back from world 42: 247 rows from 11 source systems (24 attack, 10 pension camp, 213 routine), `kestrel_sim/live.py` |
| Seeds | Training worlds 7–10. Held out: 11 and 42 (demo world). Later events: world 42 with the 22 Sep feed. Cutoff for "past-only" models: 2 Sep 2026 |
| Labels | `docs/ml/labeling.md`. Cases are labelled by the scenario instances they touch; look-alikes are the legitimate twins. Labels come from the generator, never from a model. |
| Generator hides outcomes | Ground truth (`strand`, scenario labels) is never read by detection. The live API reveals the feed's ground truth only after a run ends. Replay plans schedule by source system, not by label. |
| Schemas | Loom tables `backend/app/loom/models.py`. Final-round additions: `feed_receipt`, `case_revision`, `council_run`, `aa_consent`, `aa_fi_txn` (Alembic `9b2f4e6a1c03`, `c4d7e2f9a815`, `d5e8f1a2b3c4`) |
| Graph features | `docs/ml/features.md` (32 M7 features, each linked to the records behind it) |

## Limitations and unsuccessful cases

- **Rules still win in places.** M7 misses the demo world's 8 Sep circular loop, which stays P2 under the
  rules. On later events RB-2 ranks better than M7 (PR-AUC 0.92 vs 0.84).
- **M2's original threshold failed.** It caught 0 of 24 insider sessions on unseen worlds. It was fixed
  on held-out evidence (ADR 021), but M2 precision at 2% is only 0.24.
- **Small positive classes.** 33 suspicious held-out cases and 60 insider sessions: the intervals are wide.
- **Synthetic only.** No public dataset links staff access to money. Results describe Kestrel-Sim's
  assumptions, not a real bank.
- **Groq not verified live.** The council agents were tested only against a scripted fake (no key). The
  free tier's listed 8K tokens per minute makes a full council slow.
- **Account Aggregator** ran only against the synthetic FIP.
- **Cost of recompute.** Detection is a full 90-day recompute per checkpoint (≈80 s on the test laptop).
  Intermediate revisions differ between arrival orders by design; only the converged state is invariant.
